# Disabled scoped invitation join

Task 52 uses the exact server-only group-management archive
`689779f7aa5315954d3a313fc5b17ce1d2178ebe`; it does not re-pin the plugin's reviewed core.
`GroupJoinHttp` calls the real login, invitation acceptance, live discovery and installation
routes with strict payload/reply/facet checks and the scoped protocol header. Disposable
integration recovers the same accepted member and same enrolment attempt/token and verifies
no recipient personal device or unrestricted vault membership. The unchanged production
management/discovery hook still returns 503.

`ScopedJoinFlow` is a disabled portable controller with mandatory host ports for protected
scoped ledger allocation/reopen, complete authorized manifest, unmanaged local-path inventory
and pull-only placement. It persists the exact attempt before network effects; account/password
stay transient, invitation and `absi_` installation secrets stay in the device keychain. Keychain
proofs independently bind the issuer/account request header, accepted member/role and complete
installation descriptor/token, preventing a changed local descriptor from redirecting credentials
or switching the grant. A cancelled UI generation cannot continue installation effects in a
replacement dialog. Recovery expiry and missing retained ledger hold instead of reminting.

Only one connection may own a local vault. Personal/retained metadata refuses beginning a scoped
join. A scoped join/installation descriptor also blocks personal sign-in/adoption/engine building
before credentials/effects and refuses vault script execution independently of the activation
flag. No scoped descriptor is copied through settings/transfer. These guards include pending and
malformed descriptors: loss/corruption is not a new personal vault.

The initial pull publishes **no local files**. Unmanaged occupied incoming paths become a durable
collision hold without replacement or received-path remap. Preparing views remain explicit holds
and are rechecked from current scoped state. Native placement/ledger ports must use the strict
identity/exclusive-writer machinery; no production scoped engine starts in this task.

The Sync connect card offers a read-only preview of the disabled invitation dialog. All login/join
fields and actions remain fenced; it explains collisions, exact paths, single connection and
script-refuse policy. No password survives an attempt or closure. Actual invitation adoption,
physical scoped runtime and native connection/ledger UX are not activated or credited by this UI
preview. Native narrow-screen inspection is recorded separately from the portable/API evidence.
