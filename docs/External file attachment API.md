# External file attachment API

Stage 2 provides explicit, code-only `AttachmentStore` access through the personal engine build's `attachments()` and the scoped host's `attachments()`. Calling the factory activates durable external state and the downgrade marker; construction and ordinary sync never evict. No UI or automatic policy invokes these methods.

Eviction first finishes ordinary sync outside engine exclusivity, then reserves the original, projection and staging paths, checks pin/open/use state, verifies the exact live server head and decrypted bytes, commits a prepared operation, installs a verified projection and commits delete intent. Immediately before deletion it hashes the original again; a mismatch leaves the original intact. Reclaimed bytes count only a confirmed original deletion. The server check is point-in-time, not a server lease. An independent program can write the original in the instant between the final hash and unconditional removal; that edit can be lost. The verified previous bytes remain subject to ordinary server access and retention. No claim of exclusion of independent writers is made.

Hydration downloads the requested version into an operation-owned incoming file, verifies its size and SHA both before and after writing, commits ready-to-install and installs without intentionally replacing a target. Desktop uses native link; mobile checks target absence immediately before adapter rename. Another writer can create the mobile target in that last check-to-rename interval; this accepted residual race does not authorize copy or a check-then-write fallback. Existing targets are preserved, even if their content matches. An unchanged sidecar and desktop staging name are retained as `cleanup-pending` because these adapters cannot conditionally retire user-editable artifacts; hydration must not report full cleanup. Sync holds that identity until cleanup is resolved.

Operation IDs are immutable: a mismatched reuse is refused. Interrupted prepared/download-intent/ready-to-install operations are held rather than blindly repeated. Restart can finish remote-only bookkeeping when a committed delete intent has a missing original and a matching projection; a reappeared original is never deleted on replay. Cancellation after an intent commit leaves it recoverable. Scoped readers and editors require the same explicit, connection/grant/warning-version-bound acknowledgement; scoped version downloads never fall back to personal blob access.

Current limits: disconnect materialization and safe sidecar retirement belong to the next task. `materializeForDisconnect()` conservatively refuses. The public core engine's exclusive scheduler is currently private; the plugin adapter binds to that scheduler, which needs a public core interface before it is a stable external integration. Tests cover the real server round trip on the fast tier; the device test uses synthetic verification and download with real filesystem/IndexedDB ports, **not** a real server on those devices. Restart, each termination boundary and complete device-server round trips remain to be verified; these are not claimed as complete stage-2 guarantees.
