# External file attachment API

Stage 2 provides explicit, code-only `AttachmentStore` access through the personal engine build's `attachments()` and the scoped host's `attachments()`. Calling the factory activates durable external state and the downgrade marker; construction and ordinary sync never evict. No UI or automatic policy invokes these methods.

Eviction inspects the selected identity/version and local bytes under engine exclusivity, releases the queue to finish ordinary sync, then reserves the original, projection and staging paths, checks pin/open/use state, verifies the exact live server head and decrypted bytes, commits a prepared operation, installs a verified projection and commits delete intent. Immediately before deletion it hashes the original again; a mismatch leaves the original intact. Reclaimed bytes count only a confirmed original deletion. The server check is point-in-time, not a server lease. An independent program can write the original in the instant between the final hash and unconditional removal; that edit can be lost. The verified previous bytes remain subject to ordinary server access and retention. No claim of exclusion of independent writers is made.

Hydration downloads the requested version into an operation-owned incoming file, verifies its size and SHA both before and after writing, commits ready-to-install and installs without intentionally replacing a target. Desktop uses native link; mobile checks target absence immediately before adapter rename. Another writer can create the mobile target in that last check-to-rename interval; this accepted residual race does not authorize copy or a check-then-write fallback. Existing targets are preserved, even if their content matches. After committing verified installation evidence and retirement intent, hydration moves the unchanged owned sidecar to a recorded operation-owned quarantine name. It validates the moved bytes and absence of the visible sidecar before completing. This retires the placeholder without extending the original-file deletion race to arbitrary recovery material: the small quarantined projection is retained, never unlinked. Changed or foreign sidecars stay held as `cleanup-pending`; an ambiguous move retains both path references and is never blindly repeated. Desktop incoming names (native links) also remain recorded as retained bytes. Completion means the original is installed and its visible placeholder is retired, not that every recovery byte has been purged.

Operation IDs are immutable: a mismatched reuse is refused. Eviction stores its original request version/revision independently of the publication result. A changed head is eligible only when ordinary sync supplies an acknowledged publication receipt for that identity, exact path, SHA and size, and those bytes match the pre-publication selection; matching server/local bytes alone are not publication evidence. Interrupted prepared/download-intent/ready-to-install operations are held rather than blindly repeated. Restart can finish remote-only bookkeeping when a committed delete intent has a missing original and a matching projection; a reappeared original is never deleted on replay. Cancellation after an intent commit leaves it recoverable. Scoped readers and editors require the same explicit, connection/grant/warning-version-bound acknowledgement; scoped version downloads never fall back to personal blob access.

Recovery may finish hydration bookkeeping only from committed installation evidence plus an unchanged recorded quarantine, absent visible placeholder and matching installed original/head. `ready-to-install` with an occupied original remains held even if bytes match. The restart suite interrupts before/after each eviction/hydration phase commit and staging, installation, original deletion and projection retirement mutation; it reopens IndexedDB and asserts that recovery/retry issues no blind mutation.

Current limits: disconnect materialization belongs to the next task; `materializeForDisconnect()` conservatively refuses. Purging retained quarantine/staging bytes is not implemented. The plugin still bridges core's private exclusive scheduler in `plugin/src/sync/engineBuild.ts`; switch that adapter to the public serialized host-job port once the independently developed core port is vendored. No second scheduler is introduced here. The live suite requires the pinned clean server archive and exercises actual personal/scoped-reader HTTP verification and downloads with real filesystem/IndexedDB ports; it also checks revocation without a personal fallback.
