## Host boundary

`SyncServiceDeps.ownerPublication` installs independently protected owner metadata and actual
reviewed personal `beforeUpload`/`onSettled` hooks. Ordinary application construction does not
provide this port. `PUBLICATION_ENABLED` remains false; no setting or environment variable
activates publication. The development-only fixture installer additionally requires a protected
isolated `Agents` context and loopback issuer. Its database and original host dependency are
removed/restored before the personal fixture context is restored.

`NativeOwnerPublication` observes a real trusted native DOM clipboard event in the active source
editor. It never handles/cancels the paste. The exact pre-paste buffer must match the current
ledger version and an independently captured complete link-cache baseline. New asset bytes must
match that clipboard image and have no previous path identity. Only the exact metadata-provided
embed insertion at the captured editor selection (plus line breaks) acquires per-link owner
introduction proof. An unrelated body edit or foreign link rewrite is not note-wide authority.
Received/native engine mutation invalidates pending paste evidence durably before placement.
Configuration/script/hidden paths and unknown configuration roots cannot be eligible targets.

Cache evidence is the native `changed(file, data, cache)` callback copied synchronously: exact
source SHA, cache SHA, generation, original token and UTF-16 offsets are checked. A missing
matching callback produces an unknown baseline, not an invented empty cache or delayed/latest
cache certification. Assets remain held until the exact note settlement exists. A bounded cache
wait has a restrictive timeout, not a fabricated success. Current local bytes and eligibility
are rechecked before publication. Unknown/inconsistent source states remain held.

Durable owner-bound checksummed rows precede effects. Operation handles and original request
bodies are preserved across core's held-subset recovery. Only an independently verified exact
wire receipt with a novel create outcome authorizes owner auto-publication. A received/adopted
asset or generic note settlement does not. `PublicationIntents` persists the immutable captured
input/delta, reconciles current CAS only before first send, and retries the same attempted body.
Authorized intrinsic sponsor proof reads supply current grant/note/version/admission evidence;
owner-add uses only the owner device, native-create only the scoped editor and its own upload
entitlement. Root-folder paths are never mirrored under the sponsor directory.

## Gate 43 scenario A

The original native-owner/real-daemon lifecycle assertions remain: scoped-secret setup,
create/push/pull/move/history, deletion/restore and revocation, script/outside-file exclusion,
and retained local data. The two former pending image assertions now execute real behavior:

- Native desktop clipboard PNG paste into a Cyrillic note, automatic owner-extra publication,
  exact flat root attachment path and bytes on the real scoped daemon, plus AssetView kind.
- Authorized scoped native-create, exact replay identity/bytes on desktop and daemon, and a
  generic private collision refusal preserving the private file identity/bytes and excluding it
  from the daemon. A scoped upload proof and intrinsic note proof are both required.
- Moving the sponsor out and back asserts admission generation greater than one, so neither
  path can accidentally pass by using a fresh-fixture generation-one constant.

The native clipboard operation takes the app-wide lock, waits for other pool leases to drain,
preserves/restores every native pasteboard item/type with exact comparison (not an overwriting
Electron `writeBuffer` loop), and drives only the owned source editor. The archive implementation
also has a real AppKit round-trip test in an isolated named pasteboard, never the global clipboard.
A pool lease does not imply that its window is open: the runner verifies a nonce-framed owned-vault
reply, opens a closed owned window under the short app gate, and requests its original closed
state afterward. Unroutable CLI/close requests are errors, not successful process-exit proof. A busy shared
resource is a failed/blocked run, never a skip or acceptance pass. Builds, styles, original local
bindings, layout and all owned server/daemon/database resources are restored by the harness.
