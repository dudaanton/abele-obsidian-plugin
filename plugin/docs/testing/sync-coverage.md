# Sync scenario coverage

This is an assertion inventory, not a release qualification or a record of passing device runs.
Scenario identifiers are stable source ordinals: S1–S134 plus S21a for the behavioral catalogue,
B1–B11 for its additional behavior decisions, and U1–U8 for the screen-flow catalogue.
Requirements are paraphrased; private notes and environments are not copied into this repository.

## Inspected revisions and meaning

- Plugin baseline: `e1235991a`; tests added on this branch are identified by their full names below.
- Server/core: abele-sync `github/main` at `2c1bd4edf316b7ec772e127df9c077d06df6de63`.
  Read from git objects: the default checkout remains at `6d0cf6e` and must not be used to validate this matrix.
- The plugin pins SDK `0.3.17-scan.3`. Server/core source tests at another ref are evidence of
  intended assertions, not proof that the pinned payload passed them.
- **covered**: a specific automated behavioral assertion covers the stated outcome.
- **partly**: tests exist, but the final column identifies an unasserted facet or contradictory behavior.
- **missing**: no specific assertion found. A source note's check mark, registration test,
  generic numbered driver, skipped test or expected failure is never counted as proof.
- Paths prefixed `abele-sync/` belong to that repository; `plugin/` paths belong here.
  Parameterized test title templates are retained exactly. Rows may share a test only where
  its body asserts each behavior; raw API tests do not prove plugin lifecycle or UI behavior.

## New focused checks

`plugin/tests/unit/syncScenarioInventory.test.ts` covers the following cases:

- Interrupted index waiting preserves the ledger, does no fallback disk walk or content
  read, then restarts without deletion or a content modification.
- Changed unindexed configuration is discovered from disk.
- A settled equal-size/equal-mtime replacement is trusted without reading its contents.
- A previously tracked ordinary file omitted from the host index remains eligible.
- A rebuild that exposes an empty partial index is discarded; an edit made while
  waiting produces exactly one current-content modification rather than a delete.
- S131 pins the approved exclusion of non-config dot-folders, including tracked-file
  absence: neither presence nor absence generates an upload or deletion.
- S132 discovers new ordinary files through bounded periodic verification, signals their
  paths and uploads exact content. Tests pin zero ordinary directory listings on the
  initial scan, verification deferred until the first sync succeeds and retained
  through later busy cycles, eight directories per poll, eventual traversal beyond
  the first batch, and confinement to the connection root without hidden-folder discovery.
  Standard and renamed configuration roots remain owned by their existing settings
  snapshot: the regression requires exactly one configuration traversal per poll.
  Verification additionally caps each poll at 256 listing rows and 128 candidate
  snapshots and yields through the metadata task budget. Ledgered files remain in this
  rotation until the host index covers them; an external edit after upload must notify
  the engine without a vault event or forced fallback scan.
  `plugin/tests/unit/syncExcludedFallback.test.ts: 132 uploads an unannounced ledgered index-excluded edit by the default fallback at 33000-file scale`
  verifies the outer latency bound with the real engine and file-system adapter:
  a quiet 33,000-file ledger, a target edited just after its snapshot, ordinary polls
  at the default 30-second cadence, and upload by the default five-minute fallback.
  No watcher exchange or explicit sync call after the edit is allowed in that proof.
  Metadata rotations can take longer than five minutes; the fallback is the bound
  for an otherwise idle, running, connected desktop, plus the scan/transfer duration.

  millisecond per stat: no task may reach 50 ms and no candidate pass may exceed 384 stat reads.

  checks do not replace native-device profiling. Unreadable directories are logged and retried next rotation;

  count and position in the rotation, without delaying startup for a whole disk walk.
